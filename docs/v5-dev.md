## 設計方針

### コンセプト
- カスタマイズしやすさ国内 No.1 のテーマを目指す（設計上の指針。リリース判定基準ではない）
- theme.json を併用したハイブリッドクラシックテーマ（フルサイト編集テーマではない）
- テーマ側の挙動はシンプルに保つ。複雑な自動調整を増やさない

### ブロックテーマ機能との関係
- ブロックテーマ（theme.json）で設定可能な項目も、**なるべくカスタマイザー側で設定できる** ようにする
- テーマ標準のカラーパレットは`theme.json`で管理し、カスタマイザーではユーザー定義色の追加だけを扱う
- テーマ標準の文字サイズは`theme.json`で管理し、カスタマイザーではユーザー定義プリセットの追加だけを扱う
- テーマ標準の余白サイズは`theme.json`で管理し、カスタマイザーではユーザー定義プリセットの追加だけを扱う
- theme.json はベースライン、カスタマイザーはユーザー向け設定 UI という位置付け

### CSS 方針
- セレクターの詳細度は**基本的に `0,1,0`**（クラス単独）になるよう設計する
  - 上書きのためだけに詳細度を上げない
  - ユーザー側での上書きカスタマイズを容易にするため
  - 詳細度を上げる必要がある場合はコメントで理由を明記
- **カスタマイザー設定で CSS に影響する項目は、直接 CSS ルールを出力せず CSS カスタムプロパティの値で上書きする**
  - 例: `:root { --ys-color-primary: #xxx; }` をカスタマイザー由来で出力し、既存 CSS は `var(--ys-color-primary)` を参照
  - 新規の設定項目を追加する場合も、まず CSS カスタムプロパティを介す設計を優先する

### 引き継ぐもの・捨てるもの
- **引き継ぐ**: カスタマイザー既存設定値（オプション名は不変更）
- **互換性の境界**: v4までに保存され得る設定値と公開済みの拡張ポイントは、v5でも可能な限り引き継ぐ
- **v5開発中の変更**: v5で新しく追加した未リリースの設定項目・識別子・内部仕様は、正式リリース前であれば完成形に合わせて変更・削除できる
- **捨てる**: サイト背景色とコンテンツ背景色の差に応じた余白自動調整（全てユーザー設定に委ねる）
- **引き継ぐ**: v4のユーザー定義色1〜3（`ys-color-palette-ys-user-{連番}`）
- **捨てる**: テーマ標準色を個別に変更するカスタマイザー設定と、カラーパレット設定に関連する独自フックの互換性
- **捨てる**: `editor-font-sizes`テーマサポート、文字サイズの重複CSS生成、関連する独自フックの互換性
- **捨てる**: WordPress 6.8 以前対応のレガシーコード

## リリースブロッカー（夏リリースまでに必須完了）

### HTML/CSS 構造の完成
- ハイブリッドテーマ化（theme.json 導入）に伴う CSS 構造の再構築
- theme.json 由来の挙動の検証と統合（`global-padding`、`alignfull` など）
- ブロックで設定可能な項目もカスタマイザーで触れるように統合

### テンプレートパーツ構造の刷新
- `template-parts/parts/` に集約されている部品を意味別ディレクトリに分離
- 分離完了後に旧 `template-parts/parts/` を廃止（後から変えるとユーザー混乱のため今回で完遂）
- パーツを任意の位置で単独読み込みできるようにする
  - パーツファイル冒頭で必要情報を自前取得する形式を基本に
  - 既存のクラス経由パラメータ渡しも並行サポート（ystandard-toolbox 互換）

### カスタマイザー構造の再編
- カスタマイザーの階層を浅くする
- デザインパネルの廃止・分割
- 投稿タイプ別設定の新設（階層あり / なしで項目を自動判定）
- メタボックス対応に伴い、ブロックが無い項目もブロックエディターコンポーネントでPost metaを登録できるように設定画面を刷新する
- オプション名は変更せず既存設定値を引き継ぐ

### `ys_get_template_part` 廃止
- WordPress コアの `get_template_part` に統一
- 既存の呼び出し箇所（約 24 ファイル）をすべて置き換え
- スラグにファイルパスを渡す独自挙動は、コア関数で吸収できる形に再設計

## リリース後でよい項目

- クラスのシングルトン化 — エラーが出ない限り急がない。v5 リリース後に段階的に対応

## 実装方針詳細

### 投稿タイプ別設定の新設

#### 概要
- 旧 `inc/post/class-post-customizer.php`（投稿・固定ページ専用）を廃止済み
- 新 `inc/post-types/` に集約。公開投稿タイプ全般をサポート
- 「デザイン」パネル内の投稿ページ・固定ページ設定は削除

#### 投稿タイプ検出ロジック
- `inc/utils/class-post-type.php` の既存機能を活用
- `get_post_types(['public' => true])` で取得
- 除外: `attachment`、必要に応じて WP 標準投稿タイプ以外
- 階層判定: `is_post_type_hierarchical()`
- フォールバック: `get_fallback_post_type()` で `post` または `page` の設定を流用

#### 設定項目（階層なし: post like）
- レイアウト（1col / 2col）
- アイキャッチ画像表示タイプ（default / full）
- 本文エリア背景色
- 記事上部: アイキャッチ表示、投稿日・更新日、カテゴリー
- 記事下部: カテゴリー・タグ、著者情報、関連記事、次前記事

#### 設定項目（階層あり: page like）
- レイアウト（1col / 2col）
- アイキャッチ画像表示タイプ（default / full）
- 本文エリア背景色
- 記事上部: アイキャッチ表示、投稿日・更新日
- 記事下部: 著者情報

#### カスタマイザー配置
- 投稿タイプごとに独立したセクションを作成
- セクション名: 「[投稿タイプ名]ページ」
- カスタマイザートップレベル配置（デザインパネル外）
- 並び順: 標準投稿タイプ（post, page）→ カスタム投稿タイプ（アルファベット順）

#### 動的設定読み込み
- WordPress `init` アクション後に投稿タイプを検出
- 検出した投稿タイプに応じて動的にカスタマイザー設定を生成
- キャッシュ不要（投稿タイプは比較的固定）

### カスタマイザー「デザイン」パネル分割

- 新しいパネルは作らず、各設定へトップレベルから1クリックで到達できる構成にする
- 旧「デザイン」パネル内の設定は1セクションずつ移動し、段階ごとに検証・コミットする
- 第1段階: 「サイト背景」をトップレベルの「[ys]サイト背景」へ移動
- 第2段階: モバイルサイドバー設定を投稿タイプ別の詳細ページ・アーカイブページレイアウトへ移動
- 第3段階: 「目次」をトップレベルへ移動し、空になった旧「デザイン」パネルを廃止
- 第4段階: サイト全体・コンテンツ表示・機能連携の順に`[ys]`設定の優先度を整理
- 旧モバイルサイドバー設定は、新しい投稿タイプ別設定が保存されるまで互換値として使用する

### 設定画面刷新
- メタボックスで管理している投稿ごとの設定を、ブロックエディターコンポーネントで扱えるようにする
- ブロックが存在しない機能でもPost metaを登録・更新できる仕組みを用意する
- 既存の投稿メタ設定値は引き継ぎ、ユーザーが再設定しなくてよい形にする

### カラーパレット設定
- テーマ標準色は`theme.json`で提供し、カスタマイザーからは変更できない
- カスタマイザーのトップレベルに「[ys]ブロックエディター」セクションを配置し、1クリックで設定へ到達できるようにする
- セクション内に背景色付きの「色定義」見出しを配置する
- ユーザー定義色は`ys-color-palette-ys-user-{連番}`で管理し、v4の1〜3を引き継いでv5では1〜6を登録できるようにする
- カスタマイザーの色設定は`@wordpress/block-editor`の`ColorGradientControl`と同じトグル構造を使用し、ポップオーバー表示と4桁・8桁HEXによる不透明度設定に対応する
- 各設定名をコントロール上部と色選択ボタン内の両方へ表示する
- コントロールの枠線はWordPressの実験的なクラスへ依存せず、`ys-color-palette-control__item`で管理する
- Global Settingsのパレットは「テーマ」「デフォルト」「カスタム」の色定義元ごとにグループ表示する
- パレットのグループ名はWordPress本体と同じ翻訳コンテキストを使用する
- JavaScriptはJSXで実装し、`wp-scripts`が生成する`.asset.php`から依存スクリプトとバージョンを読み込む
- テーマ標準色を変更する旧設定値と、関連する独自フックは引き継がない

### 文字サイズプリセット設定

- カスタマイザーの「[ys]ブロックエディター」内に「文字サイズ定義」を配置する
- 設定枠は6件とし、slugは`ystd-font-size-preset-1`〜`ystd-font-size-preset-6`で固定する
- ラベルがあり、選択した種類に必要な値が有効な設定だけを設定番号順でテーマ標準プリセットの先頭へ追加する
- 種類は固定値とfluidを`ToggleGroupControl`で切り替える
- 固定値はテキスト入力とし、数値だけの場合はpxを補い、単位付きの長さ、`calc()`、`clamp()`を受け付ける
- fluidのminとmaxは0〜999とし、remは0.1刻み、pxは整数に限定する
- fluidの単位はremとpxを`ToggleGroupControl`で切り替え、初期値をremとする
- 保存値は`wp_theme_json_data_theme`でtheme originへ追加し、Global StylesのCSS生成を使用する
- テーマ標準プリセットは`theme.json`を正本とし、`editor-font-sizes`テーマサポートと独自CSS生成は廃止する
- `ys_editor_font_sizes`、`ys_is_enqueue_font_size`、`ys_is_enqueue_block_editor_font_size`は引き継がない

### 余白プリセット設定

- カスタマイザーの「[ys]ブロックエディター」内に「余白定義」を配置する
- 設定枠は6件とし、slugは`ystd-spacing-preset-1`〜`ystd-spacing-preset-6`で固定する
- ラベルと値が有効な設定だけを設定番号順でcustom originの先頭へ追加する
- 値はテキスト入力とし、数値だけの場合はpxを補い、単位付きの長さ、`calc()`、`clamp()`、`min()`、`max()`を受け付ける
- 2件目以降の設定は、設定の境界が分かるように60pxの余白を空ける
- 保存値は`wp_theme_json_data_user`でcustom originへ追加し、既存のcustom originとtheme originのプリセットを維持する
- Global StylesのCSSカスタムプロパティ生成を使用し、padding、margin、block gapなどの余白コントロールから選択可能にする

### `ys_get_template_part` 廃止
- 実態は `\ystandard\Template::get_template_part`
- WP コアの `get_template_part` に一本化
- スラグにファイルパスを渡した際に該当ファイルを include する独自挙動は、コア関数で再現可能か要検証。再現できない場合は呼び出し側を書き換える

### `template-parts/parts` 整理
- `template-parts/parts/` の各ファイルを、意味カテゴリーごとのディレクトリに分割して `template-parts/` 直下へ配置
- 参照している箇所も合わせて更新
- 旧 `parts/` ディレクトリは廃止
