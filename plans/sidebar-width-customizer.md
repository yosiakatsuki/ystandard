# レイアウトセクションの幅・間隔設定設計

## ステータス

- 実装済み
- 対象範囲のPHPUnit、PHPCS、PHP構文チェック、翻訳ファイル検証、`git diff --check`を実行済み
- 全体PHPUnitは今回の変更対象外にある既存テスト15件のエラー・失敗により未完了

## 目的

サイト全体のレイアウト設定をまとめるトップレベルの`[ys]レイアウト`セクションを新設し、コンテンツ幅、コンテナ幅、2カラムのサイドバー幅、メインコンテンツ・サイドバー間の間隔を、追加CSSを書かずにテーマカスタマイザーから変更できるようにする。

設定はサイト全体で共通とし、投稿タイプごとの1カラム・2カラム設定やモバイルサイドバー表示設定とは分離する。

設定は`コンテンツ領域`と`サイドバー`の独自ラベルで区切り、トップレベルから1クリックで到達できる構成とする。

## 設計方針

### サイト全体で1つの設定にする

現在のサイドバー幅はCSSカスタムプロパティ`--ystd--sidebar--2col--size`でサイト全体に定義され、詳細ページとアーカイブページの2カラムレイアウトで共用されている。

既存の責務に合わせ、サイドバー幅もサイト全体で1つの設定とする。投稿タイプ別の幅設定にはしない。

### 未設定時の表示を変更しない

現在の初期値は次の可変幅である。

```css
--ystd--sidebar--2col--size: clamp(12.5rem, -36.955rem + 77.27vw, 21rem);
--ystd--sidebar--2col--gap: 2rem;
```

カスタマイザー設定の初期値は空文字とし、未設定時はインラインCSSを出力しない。これにより、既存サイトと新規サイトのどちらも現在の200px〜336pxの可変幅と`2rem`の最低間隔を維持する。

設定値が保存されている場合だけ既定値を上書きする。単位のない数値には`px`を補完し、単位付きの値や許可したCSS計算式はそのまま使用する。

### メインカラムの上限幅を維持する

メインカラムは、コンテナの残り幅を無条件にすべて使用せず、サイト全体のコンテンツ幅を上限とする現在の計算を維持する。

```css
--ystd--content--2col--size: min(
	calc(100% - var(--ystd--sidebar--2col--size) - var(--ystd--sidebar--2col--gap)),
	var(--ystd--content--width)
);
```

計算順は次のとおりとする。

- コンテナ幅からサイドバー幅とカラム間の最低間隔を引く
- 残り幅とコンテンツ幅のうち、小さい方をメインカラム幅にする
- メインカラムがコンテンツ幅の上限に達した後の余りは、既存の`justify-content: space-between`によってカラム間へ配分する。このため、設定値は固定値ではなく最低間隔として扱われる

今回の設定追加では、メインカラムを`1fr`へ変更しない。コンテンツ幅、幅広ブロック、本文背景色ありの既存表示も変更しない。

### レイアウト設定をまとめるセクションを追加する

カスタマイザーのトップレベルへ`[ys]レイアウト`セクションを追加する。

セクション内は`コンテンツ領域`と`サイドバー`の独自ラベルコントロールで区切る。

`[ys]レイアウト`セクションの表示優先度は`1090`とし、`[ys]フォント・文字色`の直前へ配置する。カスタマイザーのトップレベルから1クリックで設定へ到達できる構成とする。

### 段階的に設定を追加する

レイアウトセクションは次の段階で拡張する。

| 段階 | 独自ラベル | 設定 | 状態 |
|---|---|---|---|
| 第1段階 | `サイドバー` | サイドバー幅、メインコンテンツとサイドバーの間隔 | 実装済み |
| 第2段階 | `コンテンツ領域` | サイト全体のコンテナ幅、コンテンツ幅 | 実装済み |
| 第3段階 | 各ラベル | カラム間隔など、必要性が確認できた設定 | 未確定 |

第3段階以降の未確定な設定は、必要性が確認できるまで登録しない。

## 入力値

どちらの設定もCSSの長さ・割合・計算式を文字列として保存する。数値だけが入力され、単位がない場合はCSS出力時に`px`を補完する。

入力例は次のとおりである。

- `300` → `300px`
- `18rem` → `18rem`
- `30%` → `30%`
- `calc(30% - 2rem)` → `calc(30% - 2rem)`
- `clamp(200px, 25vw, 480px)` → `clamp(200px, 25vw, 480px)`
- `var(--custom-sidebar-width, 300px)` → `var(--custom-sidebar-width, 300px)`

`calc()`、`min()`、`max()`、`clamp()`、`var()`を許可する。CSS宣言を追加できるセミコロンや波括弧、コメント、許可していない関数、不正な括弧を含む値は保存・出力しない。

未設定時はインラインCSSを出力せず、SCSSで定義している初期値を維持する。間隔の`0`は未設定と区別し、`0px`として出力する。

## コンテナ幅・コンテンツ幅設定

### 配置先

`[ys]レイアウト`セクションへ`コンテンツ領域`の独自ラベルを追加する。

識別子は次のとおりとする。

| 項目 | 設定値 |
|---|---|
| ラベルコントロールID | `ys_layout_content_section_label` |
| ラベル | `コンテンツ領域` |
| コンテナ幅の設定ID | `ys_container_width` |
| コンテンツ幅の設定ID | `ys_content_width` |

### `theme.json`との整合性

現在のコンテナ幅とコンテンツ幅は、`theme.json`の`settings.layout.wideSize`と`settings.layout.contentSize`を参照している。

- `--ystd--container--width`は`--wp--style--global--wide-size`を参照する
- `--ystd--content--width`は`--wp--style--global--content-size`を参照する

そのため、yStandard独自のCSSカスタムプロパティだけは上書きせず、保存値をGlobal Stylesへ反映する。

保存値は`wp_theme_json_data_user`を通じてGlobal Stylesへ反映し、次の値を同じ正本から生成する。

- 公開画面の`--wp--style--global--wide-size`
- 公開画面の`--wp--style--global--content-size`
- yStandardの`--ystd--container--width`
- yStandardの`--ystd--content--width`
- 投稿エディター内のコンテンツ幅・幅広表示

未設定時はGlobal Stylesを変更せず、テーマ、子テーマ、ユーザーカスタマイズから解決された現在値をプレースホルダーとして表示する。

## CSS出力

`Sidebar`クラスから`ys_get_css_custom_properties_args`へ設定値を追加する。

保存値は、許可する文字、関数、括弧の対応を再確認してから出力する。カスタマイザー以外からoptionを更新した場合や、各optionフィルターで不正な値が返された場合に、意図しないCSS宣言を出力しないためである。

サイドバー幅が`calc(30% - 2rem)`、メインコンテンツとサイドバーの間隔が`2rem`の場合は、既存のCSSカスタムプロパティ出力経路から次のインラインCSSを生成する。

```css
body:where([class]) {
	--ystd--sidebar--2col--size: calc(30% - 2rem);
	--ystd--sidebar--2col--gap: 2rem;
}
```

サイドバー幅はデスクトップ用2カラムGridとメインカラム幅の計算で使用されるため、本文幅も同じ値から自動計算される。1カラム表示には影響しない。

間隔は同じGridの`gap`へ使用する。デスクトップでは`justify-content: space-between`によって設定値より広くなる場合があり、モバイルでメインコンテンツとサイドバーが縦積みになる場合は上下の間隔となる。未設定時はどちらも既存の`2rem`を維持する。

どちらか一方だけが設定されている場合は、設定済みのプロパティだけを出力する。間隔の`0`は有効値として`0px`を出力する。

### 追加CSSとの優先順位

既存の追加CSSや子テーマから同じCSSカスタムプロパティを上書きする経路は廃止しない。

カスタマイザーの設定値を追加しても、より詳細度が高いセレクターや後から読み込まれる追加CSSによる上書きは引き続き有効とする。

## 実装方針

### `Layout`クラスで共通レイアウト設定を登録する

新しい`inc/layout/`モジュールを追加し、`Layout`クラスでトップレベルの`[ys]レイアウト`セクションを登録する。

`Layout`クラスはセクション、コンテンツ領域の設定、CSS値検証、Global Stylesへの反映を担当する。サイドバー設定も同じCSS値検証を利用する。

### `Sidebar`クラスへサイドバー設定の責務を集約する

`inc/sidebar/class-sidebar.php`へ次の処理を追加する。

- `ys_layout`セクション内への`サイドバー`独自ラベル登録
- `customize_register`へのサイドバー幅・カラム間隔設定登録
- `ys_get_css_custom_properties_args`への2つのCSS変数追加
- CSS値として安全に出力できるか判定し、数値だけの場合に`px`を補完する処理

サイドバー幅とカラム間隔は同じCSS値検証処理を使用する。間隔の`0`を未設定扱いにしないように、空文字との厳密比較で出力有無を判定する。

既存のモバイルサイドバー設定解決と、今回の幅設定は同じクラス内で管理するが、処理は独立させる。投稿タイプ別のモバイル表示設定には変更を加えない。

### カスタマイザーの優先度を追加する

`Customizer::PANEL_PRIORITY`へ`ys_layout => 1090`を追加する。

既存設定の優先度は変更しない。

### 基本スタイルは変更しない

次のSCSSは変更しない。

- `src/styles/foundation/custom-properties/_sidebar.scss`
- `src/styles/foundation/custom-properties/_content.scss`
- `src/styles/components/container/_index.scss`
- `src/styles/components/sidebar/_index.scss`

未設定時の可変幅・最低間隔と、メインカラムの上限を含む2カラムレイアウトの既存計算を正本として維持するためである。CSSビルド成果物も今回のPHP実装だけでは変更しない。
