# モバイルサイドバー設定の投稿タイプ別移行設計

## ステータス

- 実装済み
- 自動検証済み

## 目的

`[ys]デザイン`内の「モバイル表示でサイドバーを非表示にする」を、投稿タイプ別設定のレイアウト項目へ移動する。

詳細ページとアーカイブページではレイアウトを個別に選択できるため、モバイルサイドバー設定もそれぞれ独立させる。v4までの保存値`ys_hide_sidebar_mobile`は、新しい設定が保存されるまで引き続き有効とする。

## 設定構成

### 詳細ページ

投稿タイプ別設定の「詳細ページレイアウト」へ、次のチェックボックスを追加する。

- 設定ID: `ys_hide_{post_type}_sidebar_mobile`
- ラベル: 「モバイル表示でサイドバーを非表示にする」
- 表示条件: `ys_{post_type}_layout`が`2col`のとき

### アーカイブページ

アーカイブを持つ投稿タイプの「アーカイブページレイアウト」へ、次のチェックボックスを追加する。

- 設定ID: `ys_hide_{post_type}_archive_sidebar_mobile`
- ラベル: 「モバイル表示でサイドバーを非表示にする」
- 表示条件: `ys_{post_type}_archive_layout`が`2col`のとき

詳細ページとアーカイブページを別設定にすることで、デスクトップではどちらも2カラム、モバイルでは詳細ページだけサイドバーを残す、といった指定を可能にする。

## 旧設定との互換性

### 遅延フォールバックを使用する

新しい設定値が保存されているかを`Option::exists_option()`で確認し、保存済みなら`0`も明示的な値として採用する。新しい設定値が存在しない場合だけ、旧設定`ys_hide_sidebar_mobile`を参照する。

判定順は次のとおりとする。

- 対象の新しい投稿タイプ別設定
- 旧設定`ys_hide_sidebar_mobile`
- 既定値`false`

アップデート処理で新しい設定へ一括コピーはしない。動的に登録されるカスタム投稿タイプを取りこぼさず、旧設定を保存しているサイトの表示を更新直後から維持するためである。

### カスタマイザーの初期表示

新しい設定が未保存の場合、コントロールの`default`には旧設定値を渡す。これにより、旧設定が有効なサイトでは新しいチェックボックスも選択済みで表示され、画面表示と実際のサイドバー判定が一致する。

ユーザーが新しいチェックボックスを保存した投稿タイプ・ページ種別から、旧設定への依存を終了する。

### 維持する互換性

- 旧option`ys_hide_sidebar_mobile`は削除しない
- 旧値が有効なサイトでは、新設定が未保存の投稿タイプでも従来どおりモバイルでサイドバーを非表示にする
- `ys_get_option_ys_hide_sidebar_mobile`による旧設定値のフィルターは、フォールバック中は引き続き有効とする
- `ys_pre_is_active_sidebar`はこれまでどおり最優先でサイドバー判定を上書きできる

### 維持しない互換性

旧コントロールは登録せず、`ys_mobile_design`セクションも削除する。旧optionは互換値として読み取るが、旧画面からの編集経路は残さない。

`ys_mobile_design`へ独自コントロールを追加している拡張との互換性は維持しない。今回の移行対象は保存済み設定値と公開画面の表示結果とする。

## 表示ページの判定

サイドバー設定の解決処理は`Sidebar`クラスへ集約し、通常表示とカスタマイザープレビューで共用する。

| 表示ページ | 使用する設定 |
|---|---|
| 投稿・固定ページ・カスタム投稿タイプの詳細 | 対象投稿タイプの詳細ページ用設定 |
| 投稿一覧、カテゴリー、タグ、日付、投稿者 | `post`のアーカイブ用設定 |
| カスタム投稿タイプアーカイブ | 対象投稿タイプのアーカイブ用設定 |
| 1つの投稿タイプだけに属するカスタムタクソノミー | 対象投稿タイプのアーカイブ用設定 |
| 検索結果 | `post`のアーカイブ用設定 |
| 複数投稿タイプに属するタクソノミー、404など判定不能なページ | 旧設定 |

複数投稿タイプが混在するページでは、最後に処理された投稿へ依存して設定が変わらないようにする。投稿タイプを一意に決められない場合は旧設定へフォールバックする。

## 実装方針

### 設定登録

`Post_Type_Customizer`の詳細ページレイアウト設定とアーカイブページレイアウト設定へ、それぞれチェックボックスを追加する。

表示文字列はテキストドメイン`ystandard`の翻訳関数を使用する。既存のレイアウト設定と同様に`transport`は`refresh`とし、設定変更後はプレビューを再読み込みする。

### 設定値の解決

`Sidebar`へ「現在のページでモバイルサイドバーを非表示にするか」を返すメソッドを追加する。このメソッドでは端末判定を行わず、現在のクエリに対応する設定値だけを解決する。

`Widget::is_active_sidebar()`は、従来どおり`Conditional_Tags::is_mobile()`が真の場合だけこの判定を使用する。

カスタマイザープレビューのインラインCSSも同じメソッドを使用し、実表示とプレビューで設定解決が分岐しないようにする。

### 旧モバイル設定の整理

`Mobile`クラスから旧セクションと旧コントロールを削除する。クラスに他の役割がないため、`inc/mobile/`自体を削除対象とする。

旧optionはデータベースから削除せず、`Sidebar`の互換処理からのみ参照する。

## テスト設計

### カスタマイザー登録

- `post`と`page`に詳細ページ用設定が登録される
- アーカイブを持つ`post`にはアーカイブ用設定が登録される
- アーカイブを持たない`page`にはアーカイブ用設定が登録されない
- カスタム投稿タイプにも対応する設定が登録される
- 詳細ページ用設定は詳細ページが2カラムのときだけ表示される
- アーカイブ用設定はアーカイブが2カラムのときだけ表示される
- 新設定の初期値が旧設定値を引き継ぐ
- 旧コントロール`ys_hide_sidebar_mobile`と旧セクション`ys_mobile_design`が登録されない

### 互換性と設定解決

- 新設定が未保存なら旧設定`true`を引き継ぐ
- 新設定の明示的な`false`が旧設定`true`より優先される
- 投稿と固定ページで設定が独立する
- 詳細ページとアーカイブページで設定が独立する
- カスタム投稿タイプアーカイブで対象投稿タイプの設定を使用する
- 1つの投稿タイプに属するタクソノミーで対象投稿タイプの設定を使用する
- 複数投稿タイプに属するタクソノミーでは旧設定を使用する
- 投稿タイプを一意に決められない場合は旧設定を使用する
- `ys_pre_is_active_sidebar`による上書きが維持される

### プレビュー

- 現在のプレビューページに対応する新設定が有効な場合だけ、モバイル用のサイドバー非表示CSSを出力する
- 新設定が未保存の場合は旧設定に基づいてCSSを出力する
- 詳細ページ用設定とアーカイブ用設定を取り違えない

## 完了条件

- 「モバイル表示でサイドバーを非表示にする」が各投稿タイプの対応するレイアウト設定内に表示される
- 詳細ページとアーカイブページを個別に設定できる
- v4で旧設定を有効にしていたサイトの表示が、アップデート直後に変わらない
- 新設定の`false`が旧設定の`true`へフォールバックしない
- 通常表示とカスタマイザープレビューが同じ設定解決を使用する
- 旧「モバイル表示」セクションがカスタマイザーからなくなる
- 対象のPHPUnit、PHPCS、PHP構文チェック、`git diff --check`が成功する
